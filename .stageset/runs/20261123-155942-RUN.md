## Facts

- The engine first-chunk time is almost equal in both modes. `call_first_ms`
  p50 is 75.77 ms for sentence and 76.56 ms for latency.
- The queue wait is almost equal in both modes. `call_first_wait_ms` p50 is
  5.31 ms for sentence and 5.92 ms for latency.
- The long tail is in the WS send path after the first frame is emitted.
  `ws_after_emit_ms` max is 12.41 ms for sentence and 204.07 ms for latency.
- `StreamPauseCompressor.push` returns no audio while the last buffered sample
  is near silence. See `Code/batch/pause_compress.py:103-104`. Sentence mode
  sends raw frames. Latency mode sends the first chunk through the compressor.
- The holdback value does not fix the tail. Changing 50 ms to 8 ms leaves p95
  almost unchanged at B=48, 96, and 128. Holdback controls the trailing tail,
  not the `sil[-1]` gate.

## Guesses

- The tail size equals the silence gap before the next voiced frame. This is
  not measured per sample.

## Assumptions checked

- Both modes ran on one server. Confirmed by the single server pid in the log.
- The client mode field is accepted per request. Confirmed by 0 errors and by
  the different `max_frames` in each raw client file.

## Tried

emit on the first voiced sample. Both change the naturalness/latency tradeoff.
