## Goal

Find the cause of the audible seam at about 1.92 s in `latency` mode.
Generate `sentence` and `latency` WAVs for a short Hindi text with the default
`refHD.wav` voice and no conditioned profile.

## Observed output (trimmed)

Files: `Code/probes/out/quality/mode_compare_hindi/{sentence,latency}.wav`.
A second pair with `ARSENAL_CALL_PAUSE_MAX_MS=0` is in
`Code/probes/out/quality/mode_compare_hindi_nocomp/`. The owner heard the same
seam in both pairs. Pause compression is not the cause.

- `sentence`: 1 chunk, 124 frames, 6.00 s, cap_hit false, EOS true.
- `latency`: 1 chunk, 124 frames, 6.12 s, cap_hit false, EOS true.

The seam is near 1.92 s. `latency` mode sets `max_first_tokens=16` at
`Code/batch/server.py:1075`. `BatchedStream._text_chunks` hard-splits the first
text at 16 tokens at `Code/batch/batched_stream.py:290-299`. 16 tokens are about
24 frames, which is 1.92 s at 12.5 frames/s. The rest is a continuation. The
chunk metadata reports one job, so the split is internal to the stream.

## Result

PASS

## Facts

- The seam is a 16-token first-token split, not a pause compressor artifact.
- `first_max_frames=24` is only a floor and a text-split hint. It is not the
  frame cap. The frame formula is `max(24, min(est_chunk, max_frames))`.
- A true 24-frame first job with continuations is not reachable from payload on
  the current app. An app change is needed for a high-B low-latency path.
